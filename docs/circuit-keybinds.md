# 可绑定按键的电路基类

此功能提供可继承的抽象基类；具体使用示例是 [Yard 推进器](yard-thruster.md)。
方块必须位于已加载的 Yard 内才会响应快捷键或电路；放在主世界中不会激活。
快捷键只接受深度绑定到该方块所属 Yard 的玩家输入，使用 `YardDeepBindingPlayer.BoundYard` 判断。
普通站立附着、未绑定以及深度绑定到其他 Yard 的玩家均不能用快捷键控制它。
Yard 内的电路脉冲不要求操作者具有深度绑定。
原版电路响应入口是 `ModTile.HitWire`，`ModItem` 本身没有该入口，因此分成两个基类：

- `Common/Circuitry/KeybindCircuitItem.cs`：`KeybindCircuitItem<TTile>` 继承 `ModItem`，
  默认通过 `Item.DefaultToPlaceableTile` 放置指定的派生方块。具体物品自行提供贴图、配方；
  重写 `SetDefaults` 时调用 `base.SetDefaults()` 以保留默认放置行为。
- `Common/Circuitry/KeybindCircuitTile.cs`：`KeybindCircuitTile` 继承 `ModTile`，
  提供右键 UI、原版电路输入、快捷键输入及激活状态检测。具体方块自行设置贴图、TileObjectData 和静态属性。

继承物品基类时指定对应的方块类型，例如：

```csharp
public sealed class MyCircuitItem : KeybindCircuitItem<MyCircuitTile>
{
    public override void SetDefaults()
    {
        base.SetDefaults();
        Item.width = 24;
        Item.height = 24;
    }
}
```

`MyCircuitTile` 继承 `KeybindCircuitTile`，必须实现此方法：

```csharp
protected override void OnCircuitTriggered(int i, int j)
{
    // 只在“未激活 -> 激活”时执行一次，例如启动装置。
    // i/j 是 Yard 中整个家具左上角的存储 Tile 地址。
    // 此时 IsActive(i, j) 为 true。
}
```

`HitWire` 和快捷键现在只记录输入状态，不直接调用响应方法。
每次权威物理更新前，在 Yard 计时器处理之后，统一检测各家具的激活状态：

- 快捷键按住时保持激活；松开、修改绑定、失去输入焦点或进入界面时撤销对应玩家的按住状态。
  解除深度绑定或切换到其他 Yard 后，客户端撤销原输入，服务器在下一次状态检测时也会移除它。
- 原版电线只有脉冲，没有持续电平和断电回调。因此一次 `HitWire` 在下一次状态检测时激活，
  之后没有新脉冲且没有按键按住时，下一次检测恢复未激活。
- 激活状态是所有符合深度绑定条件的玩家快捷键输入与电路输入的逻辑“或”。只在 `false -> true` 时执行一次响应，
  保持激活期间不重复执行。连续更新都有电路脉冲时保持激活，需先出现无输入更新才能再次触发。
- 同一更新内的多格、多颜色脉冲合并为一次激活；另一输入在家具已激活时到来不会重复执行。

原先公开的 `TriggerCircuit` 已改为私有，只由内部激活状态检测调用。
派生类继续实现受保护的 `OnCircuitTriggered` 作为业务响应；外部可以通过 `IsActive(i, j)`
查询某个已放置家具最近一次检测后的状态。激活状态只在单人或服务器维护，不保存进角色或世界，
也不单独同步到客户端；客户端显示应使用已经同步的家具 Tile 状态。
基类将同步本家具范围的 Tile；自定义字段、其他家具、实体或效果仍须由派生类按 tModLoader 规则同步。
`HitWire` 会跳过整个家具的其他格，防止一根电线接到家具多格时重复响应。

由快捷键使家具从未激活变为激活时，默认还通过 `Wiring.TripWire` 向家具覆盖的线路发出一次脉冲，
兼容原版灯具、门、机关等；按住期间不会重复发出脉冲。
只有作为接收设备、无需主动输出电流时，可重写 `SendsWireSignalOnKeyPress` 返回 `false`。

将家具放入 Yard 后，右键任意家具格打开 UI，点击“绑定下一个按键”，再按下一个键完成绑定。
配置 UI 只要求处于交互距离内；实际使用快捷键时才检查深度绑定。
已经按住的键不参与绑定；Esc 取消等待，再按 Esc 或点击“关闭”退出；“清除绑定”移除该家具的绑定。
支持单个键，不支持组合键或鼠标按钮。在聊天、告示牌、箱子命名、背包、地图、绑定 UI、
暂停、失去焦点或玩家无法行动时不读取新的按住输入。
单人暂停期间停止状态检测与响应，恢复更新后重新检查输入。

绑定保存在角色数据中，以世界 UUID、Yard UUID、家具左上角局部坐标及方块完整名称标识。
每个玩家独立绑定；同一个键可以绑定多个家具。
在满足同 Yard 深度绑定的基础上，默认还须处于原版交互距离内。派生类可重写 `CanTriggerWithKey` 调整范围，
同 Yard 深度绑定条件由系统独立检查，不能通过这个重写绕过。
联机客户端只上报当前深度绑定 Yard 的按键输入，按住期间每 10 更新刷新一次；
服务器接收按住请求以及每次状态检测时，均检查所属 Yard、玩家的深度绑定、玩家状态和交互距离。
超过 30 更新未刷新、死亡或离线时移除该玩家的输入。松开请求即使已经超出交互范围也可以撤销原输入。
多个玩家按住同一家具时，一人松开不会清除其他人的输入；仅收到重复的按住包不会重新触发。

支持移动/旋转中的 Yard，使用 Yard 局部坐标保存绑定，触发时进入对应的存储和计时器作用域。
主世界家具必须先用蓝图采集进 Yard，才能配置快捷键。放回主世界后设备失效，再次采集进 Yard 后需要重新绑定。
不存在或类型改变的家具不会被触发。绑定以位置标识；同一位置重新放置同类家具会继续使用原绑定。
自定义帧布局可重写 `GetCircuitBounds`；默认实现支持 TileObjectData 多格家具及不同格高。

持续效果可重写 `OnCircuitActive(int i, int j, Yard yard)`：系统每次权威物理更新检查激活状态，
在刚体刷新后、Box2D 步进前执行一次。它与只在激活沿执行的 `OnCircuitTriggered` 相互独立，
不会重复发送电线脉冲。被致动为虚体的设备不执行持续效果。

## 人工验收

可使用推进器或其他具体派生类；只做编译验证，不自动启动游戏。

1. 将设备采集进 Yard 后右键，点击绑定按钮；按住旧键再点击时旧键不应被捕获。
   按新键完成绑定，Esc 取消等待，清除、关闭及失去焦点的行为应正常；开启自动暂停后仍能绑定。
2. 玩家深度绑定到该 Yard 后，在交互范围内按键，检查 `OnCircuitTriggered` 只执行一次及连接的原版灯具切换；按住时 `IsActive` 保持 true，
   松开后为 false，再次按下执行下一次响应。用原版开关触发同一设备，检查电线脉冲激活一次后自动恢复。
   多格、多颜色及已激活时的额外脉冲不应重复响应；停止所有输入一更新后再通电应能重新响应。
3. 检查聊天、背包、地图、死亡、失去焦点及暂停期间不误触发；取消输入后不遗留激活状态。
   保存重进后绑定恢复、激活状态重置，换世界不误用。
4. 两名玩家都深度绑定到同一 Yard，并分别配置同一设备的快捷键，检查任一玩家按键只由服务器执行，家具 Tile 状态和原版线路效果同步。
   超出默认范围的按住请求应无效果，同一键绑定的多个家具应各触发一次。
   两人同时按住后依次松开，最后一人松开才恢复未激活；断流、断线或死亡后不得无限保持按住状态。
5. 在移动/旋转的 Yard 内右键并绑定，检查范围使用可见坐标、线路不串入其他 Yard。
   检查保存重进、客户端中途加入及重新同步；放回主世界后失效，再次采集到 Yard 后重新绑定。
6. 在主世界放置设备，检查右键不能配置快捷键，接入原版电线也不会激活，`IsActive` 始终为 false。
   在 Yard 内分别用未绑定、普通站立附着、深度绑定到其他 Yard 的玩家按键，均应无响应。
   按住期间解除深度绑定或切换 Yard，检查没有其他有效输入时设备恢复未激活；放回主世界后同样失效。
