# Tile Yard 原型

基于本机 Terraria 1.4.4.9 / tModLoader 2026.07.3.0（666f6996）。

## 代码组织

按职责拆分目录，命名空间与目录保持一致：

| 目录 | 职责 |
| --- | --- |
| `Common/TileYards` | Yard 实例、状态、坐标、绑定及 `YardSystem` 世界协调；同一 partial 类的网络协调仍在 `YardSystem.Network.cs` |
| `Common/Storage` | Tile 底层存储扩容、二维地址分配 |
| `Common/Persistence` | 世界/Tile V2 序列化、箱子与告示牌原版存档适配 |
| `Common/WorldEditing` | Tile 和物件搬运、Yard 纹理帧刷新、目标区域清理、放回位置与稳定等待 |
| `Common/Networking` | 网络包类型、压缩分块、片段重组及物件同步 |
| `Common/Rendering` | 图块/墙/线路绘制、树木外观与几何、风摆、深度绑定视角及世界画面缓存 |
| `Common/Lighting` | 发光采样、轮廓采光、传播和缓存 |
| `Common/Physics` | Box2D 世界生命周期、单位换算、主世界静态碰撞、Yard 动态刚体及玩家几何查询 |
| `Common/Players` | 蓝图框选、入服同步、施力测试器输入、普通/深度 Yard 绑定及家具坐下/睡眠锚点 |
| `Content/Items` | 蓝图及施力测试器物品与交互 |
| `Content/Commands` | `/yard` 命令 |

世界和 Tile 存档使用 V2；Yard 元数据增加速度字段，网络协议使用版本 4，物品内容名称保持原定义。

## 游戏内操作

1. 用 **1 个木材**徒手合成「结构蓝图」。暂用原版书籍图标。
2. 手持空蓝图，左键点击选区的第一个角；移动鼠标查看蓝色预览框。
3. 再次左键点击对角，包含两个角在内的矩形将被选中；右键取消。
4. 包含方块、背景墙、电线、致动器或液体的格子完整迁移到 Yard，原格清空，蓝图绑定 YardId。
5. Yard 从原位置开始受重力运动，实体方块与主世界地形和其他 Yard 碰撞；玩家可站在实体表面，接触后普通绑定并随动。
6. `/yard list` 查看全部 Yard 的 ID、实际存储 Tile 坐标和宽高。
7. `/yard render` 切换 Yard 绘制。关闭后应看到原区域已被挖空。
8. 已绑定的蓝图左键显示区域信息；右键将 Yard 按**当前所在位置**放回主世界。更换物品或死亡会取消未完成框选。
9. 保存退出后重新进入，Yard 数据和蓝图引用应恢复。
10. 放回先以局部原点（基准 Tile）吸附到最近的世界格，忽略当前旋转并恢复初始未旋转姿态。
    等待 12 个游戏更新（正常速度约 0.2 秒），基准格不变即执行放回；亚格抖动和旋转不影响稳定判定，
    基准格移到另一格则取消，需要再次右键。暂停期间不推进等待。
11. 点击时和实际执行前都检查整个矩形是否在世界内；越界不破坏任何世界内容。
    放回强制替换整个矩形，**包括 Yard 的空气格**。原有方块、墙、电线和致动器通过原版破坏/掉落流程移除；
    液体清空，箱内物品先完整掉出，家具按正常整件破坏规则处理，可能影响矩形外与其相连的部分。
    成功后移除 Yard 记录并清空蓝图绑定，蓝图可再次框选。
12. 用 **1 个木材**徒手合成「Yard 施力测试器」（原版扳手图标）。手持并按住右键，
    再按方向键或当前移动键绑定，对所有已加载 Yard 的质心持续施力；松开方向或右键停止新增力。
    施力按质量缩放，向上可克服重力；右键按住期间，移动键用于控制 Yard。

## 坐标和所有权

Tile 地址和选区尺寸以格为单位，1 Tile = 16 像素；结构局部位置和世界 Transform 以像素为单位，角度为弧度。

存储从 `(10000, 0)` 开始，和原始选区的位置无关。自定义世界宽度超过 10000 时，起点改为世界宽度，避免覆盖主世界。
`YardStorageAllocator` 使用不旋转矩形的先左后右、先上后下首次适配：固定候选 X，优先向下寻找能容纳完整矩形的空隙；
放不下时，从已有矩形的右边界按 X 递增继续检查，并重新从 Y=0 开始。Y 最大排他边界为物理存储高度与 32768 的较小值。
不同高度、不同宽度的 Yard 可以紧贴排列，不留间隔，也不为每个 Yard 独占整列。
例如存储高度为 120，连续创建两个 50×50 Yard 会占据 `(10000, 0)` 和 `(10000, 50)`；
第三个 50×50 放到 `(10050, 0)`，后续 20×20 仍能填入 `(10000, 100)`。
放回后释放的矩形立即参与后续分配；不移动或旋转已有 Yard，也不保证全局最优排布。
算法跳过被占用的区间，不逐格扫描；最坏 O(n²)，与 Tile 面积无关。最大实际坐标为 32767，排他边界允许为 32768。
每次最多选 65536 格（包括空气）；超限时保留选区，可以缩小后再点击。

每个 `Yard` 实例保存 `YardId`、原位置、独立的 `StorageOrigin`、`Width`、`Height`、世界位置/旋转、速度以及树木外观绑定。
世界级 `YardSystem` 负责实例注册、创建、存取档、统一更新及持锁的 Tile 搬运。
物品存档只保存 `YardId`，不会在物品内部复制结构内容。跨世界携带物品不会搬运 Yard。
蓝图运行时通过 `YardBinding` 持有实例引用；创建成功直接绑定，读档后首次使用或显示提示时按 ID 绑定一次。
单人放回直接调用 `Yard.TryBeginReturn`；联机时由客户端发请求、服务器调用同一实例操作。读取信息不反复查询注册表。
世界切换通过注册表的 `WorldRevision` 使绑定重新解析；找不到 ID 的结果也按世界版本缓存。
物品克隆保留同一个 Yard 引用，但有独立的绑定对象，重新绑定一个物品不会修改另一个。
运行时唯一有效 Tile 状态在 `Main.tile[StorageOrigin.X + localX, StorageOrigin.Y + localY]`；渲染直接读取它。

## 实例生命周期

`YardState` 显式区分 `PendingLoad`、`Ready`、`Returning`、`Removed` 和 `Unloaded`。
构造函数只创建元数据，不扩容或修改 Tile。`YardSystem.TryCreate` 在校验和搬运成功后返回可用实例；
读档先创建 `PendingLoad` 实例，恢复 Tile、派生数据和动态刚体成功后转为 `Ready`，释放原快照。
缺少内容或恢复失败仍保留 `PendingLoad` 和原快照，不会误标为可用。

放回等待器及完成回调属于单个 Yard，由世界每次更新调用实例的 `Update`。
`Returning` 仍可正常渲染；锚点移动或实际放回失败时恢复 `Ready`，成功则进入 `Removed`。
放回成功立即释放对应的动态刚体。世界清理或 Mod 卸载将其余实例设为 `Unloaded`，释放刚体，
清除等待回调、快照、树木绑定及轮廓。
这两种终止状态都拒绝后续变换和放回调用；保留旧引用不会误操作新世界。
蓝图再次读取绑定时，`Removed` 会清空 ID，而 `Unloaded` 保留 ID，供重进原世界后重新绑定。

实例提供 `StateChanged` 和 `Invalidated` 事件供其他运行时模块通信。
通知订阅者抛异常会记录日志，不打断已提交的 Tile 搬运或其他订阅者；失效后释放订阅。
蓝图通过绑定访问时检查状态，不订阅实例事件，避免世界实例长期持有已丢弃的物品。
生命周期状态、等待进度和运行时引用均不进入存档；仅支持当前世界 V2 / Tile V2 格式及完整元数据，不提供旧存档迁移。

## 坐标变换与搬运

`YardCoordinates` 集中负责三种空间：固定的 Yard 存储 Tile 地址、以结构左上角为原点的局部像素、主世界像素。
`LocalTileToStorage/StorageToLocalTile` 只处理整数寻址；`LocalToWorld/WorldToLocal` 处理刚体平移/旋转；
`StorageTileToWorldCell` 用变换后的格中心采样世界风力，`TryWorldToStorageTile` 提供点击交互使用的反向查询。
放回专用的 `NearestWorldAnchorTile` 将当前 `WorldOrigin` 四舍五入到最近格子（半格时向正方向取整）；
`StorageTileToPlacementCell` 用这个锚点加局部 Tile 偏移，忽略显示旋转。
`YardReturnPlacement` 记录锚点并检测连续 12 个更新的稳定性；恢复操作不读取历史 `Source` 作为目标位置。
点和向量分开转换，向量不受平移影响；负局部坐标按 floor 定位，避免错误命中第 0 格。
可见性通过逆变换视口四角并扩展树冠余量计算；不再使用原选区作为当前显示边界。

`YardRenderContext` 提供有边界检查的 Tile 读取、Yard 局部光照、世界风力/玩家扰动查询和统一绘制出口。
所有 Yard 图层都先在局部像素空间计算，最后统一转换位置并叠加结构旋转；不修改相机或全局 Tile 空间。
`Yard.SetTransform(worldPosition, rotation)` 同时设置动态刚体和显示姿态，保留存储地址、原框选位置和速度。
物理更新使用独立的 `ApplyPhysicsState` 写回姿态及速度，不会反向重复瞬移刚体。姿态与速度随世界保存。
`Coordinates` 始终使用最新权威姿态；多人客户端单独通过 `RenderCoordinates` 使用插值后的显示姿态，
不会将显示延迟写入放回判定、物理状态或存档。
初始姿态位于原始选区且旋转为零，随后由 Box2D 计算运动；目前没有游戏内移动操控工具。
物理实现见下文。基础风摆仅将世界水平风投影到局部 X 轴。

方块、背景墙、红蓝绿黄四种电线、致动器、液体任一存在，即视为有内容。
无需包含前景方块，可以框选纯背景墙或纯线路。完整保留对应的油漆、涂层、帧及状态。
彻底空白格会跳过，过期的 TileType/帧值不算独立内容。
搬运本身不调用 `KillTile`，不产生掉落。搬运提交后及读取世界存档时，单人/服务器通过
`YardTileFraming` 重算 Yard 内普通方块、平台和背景墙的纹理帧。区域外按空气处理，
断开的边缘和角落使用正确的独立纹理，内部仍按原版规则连接、混合；保留随机帧变体。
家具、树木等其他 frame-important 图块保留原有样式和分段帧，不执行支撑破坏检查。
新帧进入既有 Tile 快照和网络事件，客户端直接使用服务器提供的结果。

刷新在 `WorldFile.IOLock` 内同步执行：临时切换到只含该 Yard、外围 12 格空气的 TileData 网格，
避免原版越界保护跳过存储地址，也避免把紧贴存储的其他 Yard 算作邻居。
临时复制所有已初始化的 TileData，包括其他 Mod 的数据；不调用 `Tilemap` 构造函数。
退出时（包括 framing hook 抛异常）恢复真实 Tilemap、数组指针、长度、世界尺寸和全局开关；
只写回纹理帧，不写回方块类型、支撑破坏或其他 Tile 状态。禁用临时网格的地图更新和 Tile actions。
刷新失败记录日志并保留原始帧，不撤销已提交的搬运或拒绝有效存档。

全部源格清空并确认搬运成功后，原选区外围一圈（含四角）逐格调用
`WorldGen.TileFrame(resetFrame: false, noBreak: false)` 和 `Framing.WallFrame(resetFrame: false)`。
周边方块与墙重新连接纹理，失去支撑的植物/家具按原版规则破坏、掉落并传播后续邻格更新。
这一步只更新主世界，不更新 Yard；单个邻格更新异常会记录日志，不撤销已经成功的搬运。

## Tile 存储扩容

`TileBackingStore` 适配当前版本的全局 `TileData<T>` 存储：

- 保持物理 Height 不变，仅扩展 Width，保留 `TileId = x * Height + y`。
- 按需扩宽，256 列对齐；不预先分配到 32767。
- 枚举 `OnSetLength` 中已初始化的各个 `TileData<T>`，包括其他 Mod 的数据类型。
- 先分配、复制、固定所有新数组，再切换指针和长度；失败时保留原数组。
- 不调用 `Tilemap` 构造函数，避免它重置世界数据。
- 扩容不修改 `Main.maxTilesX/Y`、世界边界、地图尺寸或世界生成范围；上文的 framing 临时网格仅在同步回调期间替换查询尺寸，随后恢复。
- 与 `WorldFile.IOLock` 互斥，避免在原版世界快照与 Mod 快照之间搬运。

这是针对当前 tML 私有实现的适配器，版本升级时要重新验证。
它会增加整列 Tile 存储，内存开销取决于世界存储高度和各类 TileData 大小；
其他 Mod 如长期缓存 `GetData<T>()` 返回的数组，需要单独适配其缓存。

## 渲染接入点

使用 tML 已提供的 `ModSystem.PostDrawTiles`。
本机反编译的 `Main.DoDraw` 在结束普通 Tile SpriteBatch 后调用
`SystemLoader.PostDrawTiles()`，然后进入 Projectile 和主要 Player 绘制。
因此本版本无需额外 IL patch。`YardRenderer` 自己 Begin/End SpriteBatch，
使用 `Main.GameViewMatrix.TransformationMatrix` 并减去相机位置。

背景墙通过 `On_Main.DoDraw_WallsAndBlacks` 在原版墙层合成后绘制，位于普通前景方块和实体之前。
墙使用原版 32×32 帧、动画偏移、油漆缓存和 Yard 局部光照，支持全亮/回声涂层。
电线与致动器通过 `On_Main.DrawWires` 加入原版线路叠加层；持线路工具或开启机械显示时可见。
四种电线按 Yard 内相邻格计算连接，区域边缘不会误连主世界或其他 Yard。
墙和线路 Hook 复用调用者正在使用的 SpriteBatch，不额外 Begin/End。
`On_Main.DoDraw` 在每帧开始时一次准备所有 Yard 的客户端插值姿态，墙、前景、线路、树木、
可见范围裁剪、风摆查询和轮廓采光统一使用这份姿态，避免同一帧各层错位。

读取真实 Yard Tile，复用 `TileDrawing.GetTileDrawData` 的尺寸/帧信息和油漆缓存，
按结构局部格坐标读取独立光照。实现了基本帧、半砖、四种坡面和致动后的暗化。
已有可见范围裁剪；没有整船 RenderTarget，没有临时替换相机/世界全局状态。

植物摆动由 `YardSwayRenderer` 接入：复用原版风力计时、`GetWindCycle` 和 `WindGrid` 扰动，
读取 Yard 的 Tile/墙/液体判断遮风，按显示坐标采样风相位与玩家扰动，光照读取 Yard 局部缓存。
支持普通草花、四向长苔藓、香蒲、向日葵等多格植物、旗帜和悬挂物、藤蔓与反向生长的海草。
多格植物以整株的顶部/底部锚点计算摆动；藤蔓从完整链根部计算，逐段连接，
即使根部不在屏幕内也保持同一条曲线，搜索不会越出所属 Yard。
同一对象一帧只绘制一次，不再叠加静态副本。沿用原版摆动设置和动画计时的暂停行为。
声明 `SwaysInWindBasic`、藤蔓集合的 ModTile 可使用相同路径；`MultiTileSway` 通过
`TileObjectData` 的顶部/底部锚点选择通用摆动。尚未执行其自定义特殊绘制或摆动参数钩子。

`YardTreeRenderer` 在树干之后单独绘制树冠和左右枝叶，覆盖普通生物群系树、宝石树、
樱花/黄柳、灰烬树、海滩/绿洲棕榈树，并补绘巨型蘑菇菌盖。
`YardTreeAppearanceResolver` 在源 Tile 清空前解析树种、树干/树冠样式、帧变体与树冠尺寸，
因此即使根部土壤没有框入也能解析原外观。普通树枝叶同时复用源世界的原版 foliage resolver。
MVP 按树格子的局部坐标保存外观绑定，允许只选树冠、枝条等片段；绘制阶段不再找土壤或根据当前位置选树种。
森林分区、雪地变体、神圣树帧和棕榈海滩/绿洲判定仅在采集时进行，移动后不会换外观。
树干与枝叶使用原版涂漆缓存，枝叶支持风摆、隐形/全亮涂层及灰烬发光层。
裁剪增加树冠外延，树冠锚点在屏幕外时仍可绘制可见枝叶。
树木外观版本和绑定列表是必需存档字段，没有树木时保存空列表，加载时不补建缺失的旧数据。
Mod 土壤使用完整内容名存档并重新解析运行时 ID；缺少对应 Mod 时保留绑定，暂不画相关树。
涂漆/涂层、光照和风摆仍实时读取，不冻结为截图。完整 ModTree 特殊绘制与落叶粒子尚未接入。

当前不承诺仙人掌地形变体、液体、特殊动画墙、
悬挂物专用火焰/粒子/发光特效和任意 ModTile 特殊绘制的完整还原；摆动不代表植物生长或机关运行。
不调用 `PreDraw/PostDraw/SpecialDraw`，也不实现全套原版渲染分层。

## 局部光照与外轮廓采光

每个 Yard 持有独立的局部光照缓存，将内部光源与**当前朝上的外轮廓面**采到的主世界光照合成。
不按显示坐标逐格采光，也不向主世界调用 `Lighting.AddLight`，因此不会产生双向光照反馈。
无内部或边界输入照到的区域为黑色，全亮涂层和独立发光贴图继续按原有渲染规则显示。

`YardLightContour` 在搬运前从源 Tile 提取轮廓，加载后从 Yard Tile 重建；轮廓是派生数据，不增加存档字段。
每格分成围绕中心的 8 个三角形，精确表示完整块、半砖和四种坡面；从矩形外沿对空三角形做洪水填充，
仅保留实体与外界相接的边，合并同格共线的半边。封闭内腔不直接采样外界，角点接触不会造成漏通；
分散结构保留多个独立轮廓。每条边保存所属局部格、局部中点和单位外法向，不将同格的多个法向平均抵消。
轮廓以未致动前景的形状以及独立的墙/液体为外形；纯线路和致动器不封闭空间。
它定义采光面，实际光照穿透和衰减仍由原版遮挡数据决定，透明物件不会因此变成实心光照遮挡。

每次刷新通过 `YardCoordinates` 变换面中点和法向，只有 `max(0, -worldNormal.Y)` 为正的面采光，
并将该值作为连续权重；精确直角旋转的浮点残差会被忽略。采样位置沿世界外法向偏移 8 像素，
使用 `Lighting.GetSubLight` 的原始插值 RGB。越出世界的采样返回零，不进入 Yard 存储区或自身缓存。
边界颜色与内部发光逐通道取最大值，再统一调用一次 `Blur`；不重复添加显示亮度，
也不把上次已经传播的结果当作新光源。移动和旋转不重建轮廓，只改变本次采样位置和权重。
刷新内部光源时顺便比较外形字节，仅在结构外形改变时重新提取轮廓。

这是朝上入光的近似：侧面光源不会直接照入竖直侧面，没有额外的 Yard 自遮挡射线检测；
主世界光照只覆盖相机附近的缓存，离屏边界可能采到零。这些限制不影响内部光源的独立传播。

`YardLightScanner` 从存储格读取方块、墙及液体，复用本机 tML 的原生发光和遮挡规则，
包括火把/灯具帧、彩色发光、熔岩/微光发光，以及 `TileLoader/WallLoader.ModifyLight`。
它绕过包含 `WorldGen.InWorld` 限制的 `ExportTo` 和包含环境光的 `GetTileLight`；
原版圣诞树的特殊根格读取限制在当前 Yard 内。Mod 光照钩子收到的是存储坐标，
依赖正常世界范围或外部状态的第三方钩子仍可能需要单独适配。

`YardLightMap` 使用原版 `LightMap.Blur` 进行 RGB 传播，采用默认空气、实心块、水和蜂蜜的衰减参数。
一格空白边缘只存在于当前局部光照图中，不读取 Yard 外的 Tile；不同 Yard 不共享缓存。
局部传播不额外套用玩家夜视/失明、当前生物群系水色等修正，始终使用 RGB 算法；
边界输入自然包含主世界引擎已经算出的光照。
`YardLighting` 在首次绘制前生成缓存，此后需要绘制时每 4 个游戏更新刷新一次；
暂停不推进刷新计时，显示隐形涂层的设置改变时立即刷新。平移和旋转不改变内部光源的局部寻址。

`On_Lighting.GetColor_int_int` 仅对世界边界外、已登记且已生成缓存的 Yard 地址提供局部颜色，
让 `GetTileDrawData` 内部依赖光照的发光贴图也使用同一结果；正常世界地址保持原版行为。
光照属于派生缓存，不增加存档字段；加载后首次绘制重建，放回主世界或卸载时释放。
原版私有发光方法通过预绑定委托复用，升级 tML 时需要重新验证签名。

## 多人联机

服务器是 Yard 注册表、存储分配和主世界 Tile 修改的唯一执行方。客户端蓝图发出 `RequestCreate` 或
`RequestReturn`，包内包含递增请求编号、背包槽位、预期 YardId 和创建选区。
服务器校验发送玩家是否存活、槽位是否仍为当前手持蓝图、ID 是否匹配；重复编号不再次执行。
请求编号在断开连接后清理，避免新连接复用玩家槽位时被旧编号阻挡。

创建成功广播 `Created`，携带服务器分配的 ID、二维存储地址、姿态、树木外观和 Tile V2 快照。
放回开始和失败/取消广播 `ReturnState`；放回成功广播 `Returned`，客户端移除实例、清空存储和相应蓝图绑定。
只有服务器运行 12 更新的稳定等待和破坏/掉落流程，客户端只镜像状态。
操作结果单独回应请求方，成功创建时服务器同步蓝图物品的绑定。
多人等待跟随服务器更新，客户端暂停不会暂停服务器。

只有单人和服务器推进 Box2D。服务器每 3 个物理更新（正常速度约 20 Hz）广播 `PhysicsTransforms`，
包含 YardId、位置、旋转、线速度和角速度，每包最多 1024 个 Yard。客户端记录最新权威姿态，不独立模拟。
显示使用单调时钟记录收到的姿态，保留最多 16 个样本，延迟 **100 ms** 在相邻样本间线性插值位置，
旋转沿最短角度路径插值，跨越 `π/-π` 时不会绕整圈。缓冲耗尽时停在最后一个姿态，不外推。
创建、全量快照、放回吸附和显式 `SetTransform` 清除旧缓冲；超过 500 ms 的断流后收到新姿态时重新建立缓冲。
连续运动不增加生命周期版本号，也不重发 Tile 快照或箱子目录；姿态包携带生命周期版本和运动序号，
客户端忽略旧包，遇到版本缺口或未知 Yard 时请求全量同步。网络协议版本为 4，联机两端需使用相同版本。

本地玩家进入联机世界后请求 `Snapshot`。全量同步复用当前 `YardWorldData` V2 内容，
从服务器当前内存状态生成，包含尚未保存的新操作，也保留未能加载的原始 Tile 快照。
不直接传输或覆盖磁盘世界文件；持久化仍由服务器原有 `SaveWorldData` 保存。
快照和生命周期事件通过 `TagIO` 编码、GZip 压缩，以最多 48 KiB 的片段发送；
压缩前后单次载荷均限制为 128 MiB。片段必须具有一致的事件类型、传输编号和版本号，并按连续偏移到达。
接收完整后才应用。重复/旧事件忽略，版本缺口、坏包或超时会请求全量重新同步。
原版世界数据包仅携带 Yard 网络版本号，不塞入大块快照。

每次快照/事件同时携带箱子和告示牌的权威目录，保留原版数组索引、名称、坐标和文字。
Yard 内的箱子以及本次放回的箱子使用 `ItemIO` 同步物品及其 Mod 存档数据；
其他世界箱子的库存继续使用原版打开箱子的同步流程。
对象移动或删除时关闭客户端相关界面，避免旧索引继续指向被搬走的对象。
主世界的清空/恢复由原版 Tile 包同步，按最多 32×32 格分块发送，并包含选区外两格的刷新范围。
随后重置原版已发送的世界分区，让可见分区重新发送、远处分区按需重载，覆盖树木/藤蔓连锁破坏等超出刷新范围的变化。
这会增加每次创建/放回后的分区同步流量。
客户端接收事件时不执行破坏、掉落或服务器存储分配。
`SetTransform` 的权威修改应在服务器进行。施力测试器使用独立的 `RequestForceInput` 包发送
手持槽位及 X/Y 方向（各为 -1、0 或 1）；方向变化立即发送，持续输入每 10 个游戏更新续期。
服务器检查发送者仍存活、可使用物品且手持测试器，每次物理步进前对当前所有已加载 Yard 的质心施力。
请求只更新输入状态，不直接推进物理或叠加力；松开右键发送停止输入，切换物品、死亡、断开连接，
或超过 30 个游戏更新未续期时自动停止。客户端只接收既有权威姿态包。

## 保存和范围

区域记录及其 Tile 快照通过 `SaveWorldData/LoadWorldData/PostWorldLoad` 保存到世界的 Mod 数据。
世界格式 V2 以 `storageX/storageY` 保存独立存储地址，取代旧的 `offsetX`。世界 V1 明确拒绝加载。
加载前校验完整注册表：存储边界、源选区、必需字段、重复 ID 和二维矩形相交；允许同一 X 区间内上下相邻。
仅在存取档期间使用序列化快照；运行时不维持第二份 Tile。
内容调色板使用 Mod Tile/Wall 的完整名称，避免加载顺序改变导致数字 ID 错配。
如果内容 Mod 缺失，保留原始快照并暂停该 Yard 的绘制，日志给出原因。
Tile 快照仅支持 V2，显式存储 `HasTile`，防止纯墙/线路格被恢复成方块；其他版本拒绝加载并保留原始快照。
姿态和树木外观元数据必须完整，缺失时报告加载错误，不提供旧版本默认值或自动升级。
新增 `velocityX/velocityY` 保存像素/秒的线速度，`angularVelocity` 保存弧度/秒的角速度；
这些速度字段缺失时从静止开始，世界 V2 / Tile V2 编码不变。动态刚体、质量及碰撞形状在加载时重建。

箱子、梳妆台和告示牌保留 `Main.chest/Main.sign` 中的原对象，物品数组、名称和文字不复制进 Yard 存档。
`YardObjectTransfer` 预先收集完整物件，在 Tile 搬运成功后统一修改 X/Y 为存储坐标；放回时改为目标世界坐标。
Tile 搬运失败时对象坐标不提交；搬运前关闭使用这些对象的玩家界面。选区必须包含整个物件并有对应的数据记录。
物品和文字继续由原版世界存档保存，Mod 物品附加数据继续走 tML 的箱子存档路径。
`YardObjectPersistence` 使用三处 IL 适配：`WorldFile.SaveChests` 保留已登记 Yard 的箱子；
`WorldFile.LoadSigns` 延后对 Yard 坐标的无用 Tile 读取；`WorldIO.ValidateSigns` 延后 Yard 告示牌的检查。
Yard 恢复完成后校验归属和 Tile；缺失内容导致 Yard 暂不可用时保留原对象。没有归属的世界外对象报告加载错误。
这些适配保留原序列化格式，不修改世界尺寸；加载时匹配不到目标 IL 则明确报错，卸载时移除全部补丁。
Yard 内的箱子、梳妆台和告示牌使用存储坐标交互，库存、名称和文字仍走原版界面与同步。
箱子持续打开的距离检查和告示牌更新中内联的距离检查都使用 Yard 局部玩家视图。

支持单人与服务器执行的多人组装/放回。TileEntity 和被截断的家具仍会拒绝搬运。
自定义 ITileData 的运行时复制支持，但其自定义存档语义
尚未支持。没有 Yard 内的常规随机 Tile 更新、左键挖掘/放置、驾驶操控或打包；已支持原版右键交互、
门和线路触发、Box2D 物理运动、地形及 Yard 之间的碰撞、玩家普通绑定，以及蓝图右键放回当前世界。NPC 尚未接入 Yard 碰撞；
玩家通过单向几何查询处理碰撞，不参与 Yard 刚体求解。

放回由 `YardWorldRestorer` 先清理目标，再由 `YardTileTransfer` 一次性写回全部格子；
不会在写入新结构的途中触发旧家具的连锁破坏。普通方块走 `WorldGen.KillTile(noItem: false)`，
普通挖掘拒绝移除的目标使用当前 tML 的原版掉落辅助方法后强制清理，Mod 的掉落规则仍参与执行。
重新部署完成后恢复主世界碰撞与原生更新；树木外观之后由主世界规则决定。
若搬运回写失败，保留 Yard 内容并清理已经写入的目标；已经发生的破坏、物品掉落与邻格更新不可撤销，
因此不会重建已经掉落过的原世界方块，避免重复掉落。

## Box2D 主世界静态碰撞

`PhysicsSystem.Load` 在 Mod 启动时建立 Box2D world。Terraria 世界清理或退出时销毁旧 world 及所有刚体，
重新建立空 world；Mod 卸载时彻底释放。地形碰撞是运行时派生缓存，不写入存档。
单人和服务器在 `PostWorldLoad` 完成后开始模拟；多人客户端只保留空 world，不扫描地形或独立推进模拟。

物理位置使用 Tile 单位：**1 Tile = 1 Box2D 单位 = 16 像素**，X 向右、Y 向下，旋转仍使用弧度。
`PixelsToPhysics/PhysicsToPixels` 提供像素与物理坐标换算，不改变 Yard 的存储寻址或显示坐标。
重力使用原版普通重力 `0.4 px/tick²`，换算为 `(0, 90)`，即向下 `90 Tile/s²`。
下落速度由 Box2D 的原生动力学计算，不额外强制截断到原版的最大下落速度。
每次游戏更新在 `PostUpdateEverything` 调用一次
`b2World_Step(world, 1f / 60f, 4)`；单人暂停、主菜单、世界生成及困难模式生成期间不推进。
这个最终更新入口在当次主世界修改和 Yard 搬运后同步碰撞，再执行模拟。

`WorldTileCollision` 按 **32×32 Tile** 分块，加载每名活动玩家中心周围 X/Y 各 **128 Tile** 的范围，
并加载有碰撞形状的 Yard 当前包围盒及下一步运动余量覆盖的地形，保证远离玩家的 Yard 仍能落在地面上。
边缘向外对齐到完整块。所有重叠范围只保留一份碰撞；不再被玩家或 Yard 覆盖的块立即释放，二者均为空时清空地形。
范围始终裁剪到 `Main.maxTilesX/Y`，不读取扩容后的 Yard 存储。不会预先扫描或加入整个主世界。

只有 `HasTile && !IsActuated && Main.tileSolid[type]` 且不属于 `tileSolidTop`、绳子或平台的 Tile 提供碰撞。
空气、背景墙、家具等非实体 Tile、平台、绳子、液体和线路不提供碰撞；实体 Tile 内的液体也不改变其形状。
完整方块为单位正方形，半砖占下半格，四种斜坡使用实际三角形。
每个非空块使用一个静态刚体，顶点位于块的局部空间；同块相邻完整方块合并为无空洞的矩形，
半砖和斜坡保留单独的形状，避免为每格建立一个刚体。

每次更新读取已加载块的碰撞形状，与缓存比较，只重建发生变化的块。
因此挖掘、放置、敲成半砖/斜坡、致动以及 Yard 搬走/放回的主世界 Tile 都会在随后同步中反映到碰撞。
未变化的块保留原刚体和形状。扫描成本随玩家和 Yard 所需块的并集增长，暂未接入 Tile 修改通知来免除逐次扫描。

玩家使用不施加反作用的 Yard 几何查询；玩家和 NPC 都不作为 Box2D 动态刚体接入。
独立 .NET 8 检查已验证静态地形能托住下落圆形、挖掘后移除碰撞、半砖/斜坡射线边界、
多玩家范围合并、玩家移动后的释放、世界边缘裁剪和销毁清理。

## Box2D Yard 动态刚体

`Yard.Physics.cs` 是 `Yard` 的分部实现，统一持有姿态、速度及可选的 `YardPhysicsBody`，
负责刚体创建、主动变换、模拟结果写回和释放。`YardPhysicsBody` 封装 Box2D 刚体与像素/Tile 单位转换。
`PhysicsSystem` 只管理共享 world、地形缓存和统一步进，从 `YardSystem` 的注册表取得当前 Yard，
不再另建 Yard 到刚体的字典；`IYardHost` 只保留世界操作和生命周期通知相关接口。
客户端 Yard 只记录权威姿态与速度，不持有动态刚体。存档 V2 和物理姿态包的字段保持不变。

每个 Yard 对应一个可平移、可旋转的动态刚体，与主世界共享同一 Box2D world。
创建时先从源选区建立刚体，成功后才搬运 Tile；搬运失败会同时释放刚体。
从存档恢复时从 `StorageOrigin` 读取实体形状，重建刚体后应用保存的线速度和角速度，失败则保留待加载快照。
客户端不创建动态刚体，记录服务器返回的权威姿态并使用插值姿态绘制。

`TileCollisionRules` 和 `TileCollisionBuilder` 由主世界及 Yard 共用：只计实体 Tile，忽略平台、绳子、
液体、墙、线路和非实体家具；完整块合并矩形，半砖和斜坡保留对应形状。碰撞与运动不调用原版 `Collision` 逻辑。
Yard 使用默认形状参数：密度 **1**、摩擦 **0.6**、恢复系数 **0**；完成全部形状后一次计算质量、质心和转动惯量。
刚体局部原点仍为结构左上角，质心由实体分布计算，不改变 Tile 存储或渲染局部坐标。
纯墙、线路、液体等无实体的 Yard 没有碰撞形状，赋予单位点质量以保留受重力运动，不添加虚构碰撞体。

每次物理更新后将刚体原点换算回像素，旋转通过返回的正弦/余弦分量用 `MathF.Atan2` 提取，
作为 Yard 的显示姿态；线速度换算回像素/秒，角速度保留弧度/秒。渲染和局部采光继续使用同一变换。
模拟和放回等待器在存取档/搬运的同一把锁内更新，保存占锁时跳过该次模拟，避免 Tile 快照与姿态来自不同状态。
放回吸附通过 `SetTransform` 同步到刚体，等待期间物理继续运行；锚点跨格仍按原有规则取消。

独立 .NET 8 检查已验证质量/质心、重力和旋转、刚体与渲染原点对应、Yard 落地及相互堆叠、
无玩家时地形加载、无实体 Yard 无碰撞、姿态/速度存档恢复、终止状态释放刚体，
以及最大批次姿态包往返和截断/非有限数据拒绝；未启动游戏。
客户端插值另行检查位置与旋转中间值、跨越 `π/-π`、重复/旧序号拒绝、同时到达的样本、
缓冲容量、断流保持及重建，以及权威姿态/存档与显示姿态分离。

## 玩家普通绑定

`YardMovementPlayer` 将“绑定哪个 Yard”与“是否脚下落地”分开保存。第一次接触实际实体形状
（包括侧面、顶头）才获取绑定；进入空气洞或仅与 Yard 外包矩形重叠不会自动绑定。
已有绑定在走路、跳跃、浮空时保持，直到玩家**整个碰撞框**离开 Yard 旋转后的宽高矩形。
边缘保留 1 像素容差。检测使用四个分离轴，既不只看玩家中心，也不使用宽松的世界轴对齐包围盒。
跳到矩形上方并完全越过上边缘也会解除绑定；目前没有向上扩展随动区域。
同时接触多个 Yard 时优先保持原绑定，不会因为落地状态改变而换绑。

`Yard.PlayerCollision.cs` 从存储 Tile 惰性建立 `YardCollisionGeometry`。
玩家查询和动态刚体使用同一个 `TileCollisionBuilder` 合并实体矩形，保留半砖与坡面；
按 16×16 Tile 桶筛选附近多边形，再调用 Box2D 的多边形接触及形状扫描。
玩家自身不创建刚体，因此无论人数多少都不会给 Yard 增加重量或施加冲量。
平台和 `tileSolidTop` 另建只供玩家查询的单向表面，支持平面、半高和向左/向右的平台斜坡。
从可支撑的一侧接近才阻挡，从下方跳起或按下/钩爪下穿时忽略；陡到不能落地的表面不会变成实体墙。
旋转后按真实支撑角点/边与平台线段检测，不用逆变换包围盒的宽度制造边缘支撑。
平台仍不进入 Yard 刚体几何。绳子、墙、液体和其他非实体家具不产生玩家碰撞。
门或线路等操作改变 Tile 后立即失效玩家碰撞及光照缓存，并在下一次物理步进前重建 Yard 刚体。
重建考虑质心变化，保持各个位置的点速度，避免开门使旋转中的 Yard 突然改变随动速度。

普通绑定保持玩家身体朝向、重力、移动输入和相机的世界方向。每次更新先去掉上次合成的载体速度，
让原版走路、跳跃和重力按相对速度运行；运动前根据 Yard 的前后姿态计算玩家所在位置的随动位移，
因此平移和旋转引起的点速度都被考虑，但玩家身体不会随之旋转。
载体位移检查主世界方块及其他 Yard；自身移动扫描 Yard 实体、消除穿透并沿接触面滑动，
之后仍由原版处理主世界碰撞、坡面、边界等。结束时仅合成一次实际载体位移对应的像素/tick 速度。
解除时保留这一世界速度，不重复继承。获取绑定的首帧点速度使用实体质心和角速度计算，
避免把 Yard 左上角误当作质心。

脚下接触法线与反重力方向的点积大于 0.64 时可落地；落地会清零相对竖直速度，重置落差、
额外跳跃、翅膀和火箭靴资源。接触扫描显式处理初始接触，避免 Box2D 忽略扫描起点重叠时穿过地板。
跃起时取消落地状态但保持矩形内的普通绑定。死亡、断线、退出世界、Yard 失效或同 ID 实例被快照替换时清理旧绑定。
渲染开关只控制可见性，不关闭碰撞。
已落地的行走按脚下坡面保持水平输入速度并计算相应竖直位移，避免每帧把重力投影为下滑速度。
离地判断检查速度是否朝支撑面的外法线运动，上坡的切向上升不会被误判成跳起。
原版 `PlayerFrame` 执行时临时使用本帧支撑下的行走速度生成动画，之后恢复实际位移速度，
避免 `PostUpdate` 才确认落地导致站立玩家持续显示下落；联机远端使用同步的落地状态。

多人模式中只有拥有该玩家的客户端执行普通绑定移动；服务器继续独占 Yard 的 Box2D 模拟。
本地玩家查询与 Yard 绘制相同的延迟姿态流，查询不修改权威姿态或存档。
`PlayerAttachment` 包在绑定/落地状态改变时立即发送，绑定期间每 3 更新发送局部中心及世界方向的相对速度。
服务器校验发送者归属、坐标有限性和局部矩形范围后转发；包不允许修改 Yard 姿态、Tile 或分配存储。
远端玩家用自己的 Yard 显示姿态还原局部中心，最多预测 6 更新的相对移动，避免原版重力使静止乘客下坠。
渲染时再补偿运动采样与本帧显示姿态的时间差，玩家身体和相机均不旋转。
入服同步携带已有乘客状态；Yard 快照尚未加载时保留状态，加载后才能采用该锚点。

当前玩家扫描使用当次 Yard 姿态，未实现高速移动/旋转 Yard 在两个姿态之间扫过未绑定玩家的完整连续碰撞，
也没有挤压伤害和卡在多个表面之间时的完整脱困策略。实际游戏移动、坐骑、钩爪及联机延迟仍需人工验收。

## 玩家右键交互与局部视图

`YardPlayerView` 在查询时逆变换玩家中心、完整碰撞框、相对速度、移动意图和重力方向。
它只提供查询数据，玩家的长期位置、相机和网络位置仍使用世界坐标。
碰撞继续使用旋转几何扫描；交互距离通过这个视图读取局部玩家信息。

`YardSystem.Interactions.cs` 在原版右键检查期间使用最后绘制的姿态逆变换鼠标，
把实际命中的非空气 Tile 换成存储目标，并适配交互距离；检查结束立即恢复原版鼠标目标。
重叠时选择最后绘制的有 Tile 的 Yard，空气洞允许后面的 Yard 或主世界响应。
UI、全屏地图、NPC 交互以及蓝图/施力测试器保留自己的输入入口。
这一步不重定向左键挖掘、放置或普通物品使用。当前右键入口仅处理原版 Tile，
自定义 ModTile 的右键逻辑仍未接入。原版座椅和床头睡眠使用独立的持久家具锚点，见下文。

箱子、告示牌和增益工作站等原版界面/玩家效果直接使用存储目标。
修改 Tile 的原版操作现在由单人或服务器直接在存储地址执行。交互用的临时网格、
全体实体坐标映射、延迟实体包与失败回滚已删除；不再替换 `Main.tile`、世界尺寸或玩家坐标。
`YardSystem.TileAccess.cs` 扩展 `WorldGen.InWorld`，只认可已加载 Yard 的存储矩形。
`Framing.GetTileSafely`、右键预览、箱子/告示牌请求和线路等调用此入口的路径随之支持存储地址。
`TileFrame`、`PlaceTile`、`KillTile`、`CanKillTile`、`CheckSign`、`PlaceSign`、`Framing.WallFrame`
还有内联边界检查，增加 Yard 成功分支，保留原版初始化及主世界检查。
`Wiring.HitWire` 的邻格遍历限制在当前 Yard，`CheckLogicGate` 的纵向扫描使用当前 Yard 下边界。

已适配的原版 Tile 辅助方法直接读写当前 Yard。区域外的邻格读取映射到一个运行时保留的空气格，
区域外的索引器赋值丢弃；箱子/告示牌目录操作也检查当前 Yard 所有权。
空气格不属于存档中的 Yard，分配器避开它，已有存储地址和 Tile ID 保持不变。
这不是对任意 ModTile 或所有原版方法的通用 Tile 访问重定向。
液体队列与主世界地图不会登记存储地址。采集后的独立纹理 framing 仍使用只读隔离副本，
已经移除该副本原先用于交互提交的接口。

线路的机械计时器/冷却表仍按 Yard 隔离，但计时器记录真实存储地址；进入/退出时只切换原版表引用，
不再复制计时器数组。常规随机 Tile 更新、压力板接触及环境碰撞效果仍未接入。
原有自动门局部玩家作用域及偏好同步已删除，暂不提供 Yard 自动开关门。
本阶段只接入存储 Tile 边界与既有交互距离；依赖玩家左右/上下位置、传送、实体出生位置、
弹幕速度或音效位置的原版逻辑仍需要分别适配，不能把边界合法视作这些交互已完整支持。

日常交互复用原版的增量同步，不再在操作前后完整编码 Yard，也不再发送 `TilesChanged` 全量事件。
`YardSystem.TileNetworking.cs` 给 `NetMessage.SendData` 的 `TileSquare` 编码增加存储区域成功分支，
跳过会把存储 X/Y 修正到主世界的边界限制；原版字段编码和 Tile 内容写入保留。
发包矩形裁剪到当前 Yard，较大的更新拆为最多 32×32 格；`RemoteClient.SectionRange` 对已加载 Yard
直接认可，避免访问原版世界分区数组。主世界包继续使用原版边界和广播条件。

`YardTileChanges` 只记录作用域中实际访问的格子，第一次访问时保存字段值，结束时局部比较。
原版通过取得的 `Tile` 直接修改字段也能被这些已适配入口捕获。已经广播的 `TileSquare` 记录发送时的状态；
没有发包、只回复一个客户端、发包后再次变化或恢复原值的格子，合并相邻横向格子后补发原版状态包。
操作包之后保留最终状态校正，避免开关/门的相对操作与状态包混用时重复切换。
比较范围是本次原版调用访问的格子和发包覆盖范围，不是整个 Yard；不提供任意 ModTile 写入的通用追踪。
`TileCount` 按这些格子的内容增减更新，不再为计数遍历整个 Yard。变化使玩家碰撞与光照缓存失效，
只有碰撞形状发生变化才在下一物理更新重建刚体；单纯灯具帧切换不会重建刚体。
直接操作不保证异常回滚；发生异常后，已捕获的部分写入同样失效缓存并补发局部更新。

多人修改请求携带 Yard ID、局部目标格和局部鼠标位置，服务器检查归属范围、交互距离、
有限数字及点击频率，再执行原版操作。客户端不修改持久 Tile。
服务器的原版 Tile/门/开关/解锁/箱子包由客户端在对应 Yard 的边界作用域内应用。
原版电路遍历仍由服务器执行，客户端只应用开关外观及收到的 Tile 状态，不推进电路计时器。
接收范围必须完整属于同一个已加载 Yard；客户端不向服务器回发应用更新时产生的 Tile 包。
箱子与告示牌 UI 继续使用原版包，服务器验证存储归属、距离及目录索引。
原版 Tile 状态包直接清掉家具时，客户端清理对应箱子/告示牌目录及打开的界面状态。
增量更新保持当前 Yard 实例与姿态插值流，不增加生命周期版本号；首次同步、重同步和创建等生命周期
事件仍使用 Tile V2 快照及对象目录。网络协议版本为 4，世界存档格式仍为 V2。
预留空气格地址随服务器的快照/创建事件提供，客户端只使用和扩展服务器指定的存储地址，不自行分配。

床与椅子的原版状态、吸附坐标和绘制形态分析见 [yard-resting-interactions.md](yard-resting-interactions.md)。
原版椅子、沙发、长凳、马桶等 `CanBeSatOnForPlayers` 家具可右键坐下，床头可右键睡眠。
`YardRestingPlayer` 保存 Yard 实例、点击局部格、规范家具锚点、局部 Bottom 以及家具类型/帧，
不会将存储像素坐标写入玩家世界位置。进入时读取原版 target info，保留家具样式、朝向、坐姿和床的视觉偏移。
进入按原版坐下/睡眠距离限制交互，不检查玩家碰撞框、目标穿透或吸附路径。
同一规范锚点每种姿态最多容纳两名玩家；占用登记使用存储锚点，多个重叠显示的 Yard 不会共享座位。

原版 `UpdateSitting`、`TryGetSittingBlock` 和 `UpdateState` 的家具定位被替换为独立锚点查询；
原版移动/跳跃、方向改变、坐骑/滑轮、睡眠活动限制、入睡计时及多人视觉偏移继续运行。
姿态期间暂停普通玩家移动和重复载体随动，每帧把局部 Bottom 还原到 Yard 当前玩家姿态。
绘制对齐本帧显示姿态，在原版坐姿/横躺绘制完成后，围绕家具锚点旋转完整玩家绘制数据及视觉偏移。
玩家身体随 Yard 旋转，本地玩家进入深度绑定视角。坐卧期间不与本 Yard 或其他 Yard 做玩家碰撞检测，
也不额外扫描主世界障碍来裁剪锚点随动或解除姿态。玩家保留原版碰撞框及弹幕、NPC 等命中/伤害流程，
原版玩家更新照常执行；锚点位置由家具控制，碰撞框不随 Yard 旋转或改为新的旋转身体轮廓。
家具被移除、致动或换帧，Yard 失效/放回，玩家死亡/断开或主动起身时清除锚点；退出一次性继承载体速度。
姿态不写入存档，重进世界后保持普通玩家状态。

多人点击沿用局部目标请求，服务器检查点击、距离、家具及占用后广播 `PlayerRest`，客户端应用权威姿态。
退出由服务器原版条件或本地退出请求触发；请求只能影响发送者的当前家具绑定。
静止姿态不发送普通乘客局部位置包，也不允许这些包覆盖服务器的家具锚点。
中途加入和全量快照之后同步家具姿态，快照未就绪时暂存锚点，加载后再采用。
床尾不设置/移除出生点，也不显示出生点家具图标；移动床的出生点保存及复活定位尚未适配。

### 深度绑定参考系

深度绑定是以绑定 Yard 为参考系的玩家状态。玩家在 Yard 上坐椅子、睡床，或进入未来支持此状态的
其他交互时，由交互显式进入深度绑定；交互结束时显式退出。椅子与床已接入通用状态和本地视角变换。

状态职责：

- 深度绑定唯一的有效性约束是存在一个有效的绑定 Yard。进入时必须提供该 Yard，
  Yard 失效、卸载或实例被替换导致原绑定失效时清理状态；不能保留没有 Yard 的深度绑定。
- 深度绑定不采用普通绑定的实体接触、落地、矩形重叠或距离条件，也不逐帧检查玩家是否静止。
  交互通常会固定玩家在 Yard 上的局部锚点、限制自由移动；这些行为由交互负责，
  不是深度绑定新增的校验条件。Yard 的平移、旋转和随动速度不会使状态退出。
- 进入和维持深度绑定都不检查玩家与 Yard 的碰撞框、穿透或移动路径，也不检测其他 Yard。
  玩家自然保留原版碰撞框及碰撞/伤害流程，供原版弹幕、NPC 等逻辑使用；
  不新增旋转碰撞框，不为锚点随动添加障碍预扫或受阻退出。坐卧已按此规则处理。
- 椅子、床的进入检查、姿态维持和起身规则仍属于各自交互；它们结束时通知深度绑定退出。
  深度绑定层不重复检查家具、姿态或碰撞。未来交互可复用状态，无须伪装成坐下或睡眠。
- 驾驶可作为未来的一种交互使用深度绑定。驾驶输入、退出操作及是否限制普通交互由驾驶功能决定，
  不作为所有深度绑定交互的共同要求。

本地视角：

- 以玩家的交互锚点为跟随中心，抵消绑定 Yard 的平移和旋转，使玩家持续位于屏幕固定位置，
  绑定 Yard 在画面中保持自身局部方向，整个外部世界相对它移动和旋转。
  这只是观察参考系变换；Yard 的世界姿态、物理模拟和服务器权威坐标照常更新。
- 若本帧 Yard 显示旋转为 `θ`、玩家锚点的显示世界位置为 `p`、固定屏幕位置为 `s`，
  世界点 `q` 的屏幕位置为 `s + Z · R(-θ) · (q - p)`，其中 `Z` 是视图缩放。
  相机、Yard 和玩家使用同一帧显示姿态，避免网络插值或角速度造成玩家在屏幕上漂移。
  坐姿和睡眠横躺继续保留各自相对于 Yard 的姿态及视觉偏移。
- 仅本地深度绑定玩家使用此视角；UI 保持正常，其他玩家各自按自己的状态观察世界。
  世界地形、背景、其他 Yard、实体、粒子及世界覆盖层须使用一致的变换，
  同时覆盖旋转后的可见范围，避免边角缺绘。
- 点击命中、鼠标瞄准和交互坐标统一使用上述视角的逆变换；涉及 Yard 的查询再转入对应 Yard 局部坐标。
- 退出深度绑定时相机立即恢复世界方向和普通跟随；普通绑定恢复仍遵循实体接触获取规则。

实现分工：

- `YardDeepBindingPlayer.Bind(Yard, Vector2)` 接收当前已加载的 Yard 实例和以局部像素表示的玩家 Bottom 锚点；
  `Unbind(Yard)` 供交互结束时解除。状态监听 Yard 失效事件，死亡、断线和世界切换时也清理。
  不额外检查接触、速度或锚点是否在 Yard 矩形内；移动限制和姿态维护由交互负责。
  玩家完整绘制数据的 Yard 旋转也由这个通用状态处理，原版碰撞框不变。
- `YardRestingPlayer` 在进入坐卧后绑定、起身时解除；服务器权威 `PlayerRest` 事件在各客户端恢复相同状态，
  普通乘客同步不能覆盖它。未来交互自行负责授权、移动和状态同步，再调用上述接口。
- `YardCameraSystem` 与 Yard 绘制共用本帧显示姿态。世界先绘制到以屏幕对角线为边长的方形画面，
  再围绕锚点反向旋转并裁切到真实屏幕，锚点固定在屏幕中心；用户缩放不会因画布扩大而改变。
  `YardSceneTargets` 为此维护独立的地形、墙、水、背景及滤镜缓存，并保存/恢复原版缓存的世界位置。
  原版和 Yard 的可见范围及光照查询在扩展视口内运行，覆盖任意旋转角度所需的屏幕边角。
- 完成世界合成后恢复真实屏幕尺寸再绘制 UI；伤害数字、世界标记等使用相同视角矩阵，地图保持正常方向。
  全屏地图与原版拍照模式暂时使用普通视角，关闭后恢复绑定视角。鼠标世界坐标先逆旋转、逆缩放，
  再交给原版瞄准与交互代码；UI 鼠标仍使用原始屏幕位置。
- 扩展缓存随分辨率或原版绘制模式改变重建，退出绑定或世界时释放。深度绑定需要比普通视角更大的
  绘制面积和显存；原版绘制/鼠标 IL 接入点基于当前安装的 tModLoader，升级后需要重新检查。

可绑定按键的电路设备现有可复用的 `KeybindCircuitItem<TTile>` / `KeybindCircuitTile` 基类，
快捷键按住状态与电线脉冲切换的开关状态取“或”，电路开关保持到下一次脉冲；
统一检测激活状态，仅在未激活变为激活时执行 `OnCircuitTriggered`。
需要持续效果的设备可通过 `OnCircuitActive` 在激活期间每次物理更新执行一次。
设备仅在 Yard 内生效，快捷键只接受深度绑定到该设备所属 Yard 的玩家输入。
继承方式、状态查询、世界共享绑定存储及人工验收见 [circuit-keybinds.md](circuit-keybinds.md)。

具体设备 `YardThrusterTile` 提供四向推进器：箭头沿贴附面的外法向表示喷气方向，以自身位置沿反方向施加持续推力，
方向随 Yard 旋转，偏心安装产生转矩。支撑破坏后掉落，推进器在主世界和 Yard 中均无碰撞。
原型用 1 木材制作，先连同支撑采集进 Yard，再右键绑定快捷键；同 Yard 深度绑定玩家可远程按键控制。
放置、脉冲持续时间及人工验收见 [yard-thruster.md](yard-thruster.md)。

施力测试器验收：用 1 个木材徒手合成「Yard 施力测试器」（原版扳手图标），手持并按住右键，

力以世界方向作用于 Box2D 计算出的质心，使用 `F = m × 180 Tile/s²`，向上可克服重力，
不同大小的 Yard 获得一致的施力加速度；施力本身不额外施加转矩，碰撞仍可使其旋转。
